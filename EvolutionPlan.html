1 · Améliorations immédiates (0–4 semaines)

Ces éléments sont soit des correctifs résiduels simples, soit des fondations indispensables pour ne pas bloquer les évolutions futures.

Haute priorité
🧪

Suite de tests automatisés

Le projet ne dispose d'aucun test. Chaque modification risque de casser silencieusement une mécanique de jeu. Mettre en place Unity Test Runner (EditMode + PlayMode) pour les systèmes critiques : combat, sauvegardes, audio, chargement de scènes.

Effort élevé Architecture
📦

Migration complète vers Unity Input System

Plusieurs scripts utilisent encore l'ancien PokemonUnity.Input basé sur l'Input Manager legacy. Le package com.unity.inputsystem 1.11.2 est déjà dans le manifest — il faut migrer tous les points d'entrée clavier/manette vers InputAction et PlayerInput pour un support gamepad et mobile natif.

Effort élevé UX
💾

Système de sauvegarde robuste

Les serializers SeriV2/V3/V4/SeriColor viennent d'être corrigés mais le format de sauvegarde n'est pas versionné. Ajouter un numéro de version de schéma + migration automatique pour éviter les sauvegardes corrompues lors des mises à jour futures.

Effort moyen Architecture
🔊

Refactorisation AudioManager

AudioData.cs instancie des AudioTrack via des getters sans pooling. En combat, cela peut créer/détruire des centaines d'objets par seconde. Migrer vers un pool d'AudioSource géré par Unity Audio (Mixer groups).

Effort moyen Performance
🌐

Localisation (i18n)

Les textes sont en dur dans le code ou dans des fichiers CSV non versionnés. Intégrer Unity Localization (com.unity.localization) pour externaliser tous les strings, noms de Pokémon, descriptions de capacités, et dialogues, avec support multilingue immédiat.

Effort moyen Contenu
🗂️

Addressables pour les assets

Les sprites, sons et données sont probablement chargés via Resources.Load(). En Unity 6, la pratique recommandée est Addressable Assets pour un chargement asynchrone, un bundling par plateforme et une réduction du temps de démarrage.

Effort élevé Performance

2 · Évolutions moyen terme (1–3 mois)

Priorité moyenne
⚔️

Système de combat révisé (State Machine)

Le système de combat actuel s'appuie sur un script monolithique BattleScene.cs. Refactoriser vers une State Machine explicite (Unity StateMachine ou custom FSM) : état IDLE, CHOOSE_ACTION, EXECUTE_MOVE, FAINT, WIN/LOSE. Rend le code testable et extensible.

Effort élevé Architecture
✨

Effets visuels des capacités (VFX Graph)

Unity 6 inclut VFX Graph avec GPU particles. Créer un système de prefab par type de capacité (Feu, Eau, Électrik…) déclenché lors des animations d'attaque. Remplace les animations sprite statiques actuelles.

Effort élevé UX
🗺️

Système de carte du monde

Ajouter une vue carte interactive avec zoom, régions, villes et routes. Utiliser Unity Tilemap (déjà dans le manifest) avec des tuiles de terrain procédurales et des marqueurs de progression.

Effort élevé Contenu
🤖

IA des dresseurs améliorée

L'IA actuelle choisit probablement les mouvements aléatoirement ou avec des règles fixes. Implémenter un système de scoring basé sur les types, PP restants et état des Pokémon pour une IA plus difficile et cohérente, configurable par niveau.

Effort moyen Architecture
📱

Support mobile natif

Avec Input System déjà présent, ajouter des contrôles tactiles : D-pad virtuel, boutons A/B/Start, pinch-to-zoom sur la carte. Adapter les Canvas pour les résolutions mobiles (Safe Area, notch support). Cible : Android + iOS via IL2CPP.

Effort moyen UX
🎵

Musique adaptative (Audio Mixer)

Utiliser les Audio Mixer Groups de Unity 6 pour une transition fluide entre les thèmes (exploration → combat → victoire) avec crossfade automatique, effets de filtre et contrôle de volume par catégorie (musique, SFX, voix).

Effort faible UX

3 · Vision long terme (3–12 mois)

Priorité basse / Vision
🌍

Multijoueur en ligne

Combats PvP, échanges de Pokémon et classement. Utiliser Unity Gaming Services (Lobby + Relay + Vivox) ou Netcode for GameObjects. Architecture : serveur autoritaire pour valider les combats, prévenir la triche.

Effort élevé Architecture
🎨

Éditeur de maps intégré

Permettre à la communauté de créer des régions personnalisées via un éditeur in-engine. S'appuyer sur Unity Tilemap + un système d'export vers des AssetBundles Addressables pour des DLC de maps.

Effort élevé Tooling
🏆

Système de succès et classement

Intégrer Unity Gaming Services — Leaderboards et Cloud Save pour une progression cross-device, des succès (Pokédex complet, champion de ligue…) et un classement PvP mondial.

Effort moyen Contenu
🧬

Pokémon procéduraux (génération)

Système de génération procédurale de Pokémon "fakemon" : stats, types, mouvements et sprites assemblés depuis des parties préfabriquées. Utiliser Unity Burst + Job System pour les calculs de génétique et d'IA de rencontre.

Effort élevé Contenu
🥽

Mode exploration 3D / AR

Exploiter le Render Pipeline URP de Unity 6 pour une vue 3D isométrique en overworld. Extension AR possible via AR Foundation pour des rencontres Pokémon en réalité augmentée sur mobile.

Effort élevé UX
🔌

API de mods / Plugin system

Exposer un système de hooks permettant des mods externes : nouveaux Pokémon, nouvelles régions, nouvelles mécaniques de combat. Architecture par Assembly Definition isolées + interfaces publiques stables.

Effort élevé Architecture

4 · Refactorisations techniques recommandées

Indépendantes des fonctionnalités, ces refactos améliorent la maintenabilité et les performances à long terme.

Refacto 1 Découplage Scene/Screen via Dependency Injection
Actuellement, les scènes accèdent aux écrans via GameManager.current.game.Scenes.X (couplage fort). Introduire un container DI léger (ou Unity's own DI via IServiceLocator) pour injecter les dépendances et faciliter les tests unitaires.
Refacto 2 EventScene → Unity Coroutine natif
Le système d'événements custom (OnUpdateEvent, OnATriggerEvent) double Unity's own coroutine/event system. Réécrire en async/await C# 9 ou en coroutines Unity pures avec WaitUntil / WaitForSeconds pour plus de lisibilité et de debuggabilité.
Refacto 3 ScriptableObjects pour les données statiques
Les données des Pokémon, mouvements et objets sont actuellement en C# pur ou CSV. Migrer vers des ScriptableObjects pour bénéficier de l'éditeur Unity, de l'inspection visuelle et du hot-reload sans recompilation.
  • PokemonDataSO : stats, types, évolutions
  • MoveDataSO : puissance, précision, effets
  • ItemDataSO : effets, utilisation en combat
Refacto 4 Profiling et optimisation mémoire
Utiliser Unity Memory Profiler et CPU Profiler pour identifier les allocations fréquentes en combat (Update loop, coroutines). Cibles prioritaires :
  • Pool d'objets pour les effets visuels
  • Éviter les closures/delegates dans les boucles serrées
  • Utiliser Span<T> / NativeArray pour les calculs de combat
Refacto 5 CI/CD avec GitHub Actions + Unity Build Server
Automatiser les builds et les tests à chaque push. Pipeline suggéré :
  • Lint C# (dotnet format)
  • Unity Test Runner (EditMode)
  • Build WebGL + Android debug
  • Upload artefacts sur GitHub Releases

5 · Exemples d'implémentation

5.1 — Migration Input System (pattern recommandé)

// AVANT — Legacy Input Manager (non cross-platform) if (PokemonUnity.Input.press(PokemonUnity.Input.A)) confirmAction(); // APRÈS — Unity Input System // Dans un MonoBehaviour avec [RequireComponent(typeof(PlayerInput))] private InputAction _confirmAction; private void OnEnable() { _confirmAction = GetComponent<PlayerInput>() .actions["Confirm"]; _confirmAction.performed += OnConfirm; _confirmAction.Enable(); } private void OnConfirm(InputAction.CallbackContext ctx) => confirmAction(); private void OnDisable() { _confirmAction.performed -= OnConfirm; _confirmAction.Disable(); }

5.2 — ScriptableObject pour données Pokémon

// PokemonDataSO.cs — données éditables dans l'inspecteur Unity [CreateAssetMenu(menuName = "PokemonUnity/Pokemon Data")] public class PokemonDataSO : ScriptableObject { public Pokemons id; public string displayName; public Types[] types = new Types[2]; public int baseHp; public int baseAttack; public int baseDefense; public int baseSpeed; public Sprite frontSprite; public Sprite backSprite; public AudioClip cry; // Référence aux évolutions via d'autres SO (pas de couplage string) public PokemonDataSO[] evolutions; public int[] evolutionLevels; }

5.3 — State Machine de combat

// IBattleState.cs — interface de chaque état public interface IBattleState { void Enter(BattleContext ctx); void Execute(BattleContext ctx); void Exit(BattleContext ctx); } // Exemple d'état : sélection de la commande joueur public class ChooseCommandState : IBattleState { public void Enter(BattleContext ctx) => ctx.CommandMenu.Show(); public void Execute(BattleContext ctx) { if (ctx.CommandMenu.HasSelection) ctx.TransitionTo(new ExecuteMoveState(ctx.CommandMenu.Selected)); } public void Exit(BattleContext ctx) => ctx.CommandMenu.Hide(); }

6 · Roadmap synthétique

Phase 0 — Terminé Migration Unity 6.3 LTS + double audit
